# Agent usage: unreleased native candidate

Based on TokensBar main `d4a1ff0966c49765a402e90400ab1236034715e5`; provider research checked 2026-10-28. This feature is not in the published v1.11.1 App. An isolated candidate branch is used for macOS CI; main is unchanged and no release was created. The existing main panel, typography and green accent are retained; the new entrance opens a separate native AppKit window.

## What this version implements

Open the panel's Actions → Agent usage, or the context menu's Agent usage item (keyboard shortcut A). The window offers My usage and Service catalog, search and Personal / Coding / API categories.

- Submitted coding activity: automatically reuses the already-configured tokens.ci daily client records for today, 7 or 30 UTC days. Shows the account, fetch time, submission time and failures. Actual returned client names, tokens and estimated USD only; does not invent empty clients. It never adds the local CLI total to submitted all-device activity.
- Optional historical/reference snapshots (not the automatic solution): add/edit/delete a local snapshot for any catalog or custom service. Record the actual unit, used amount, total allowance, reported remaining, model-token count, cost/currency, period, next reset, observation date and optional shared-pool label. Blank means unknown. Remaining is derived only from the same row's allowance minus used (clamped at zero), or from the reported remaining. Contradictory values are rejected; overage is retained. No cross-service grand total or credit-to-token conversion.
- Import/export: versioned JSON, an explicit confirmation before import, stable-ID upsert, unrelated records preserved. Imports always have imported provenance, never automatic. Up to 5 MB and 5,000 snapshots; invalid files do not partially import. The local store is `~/.config/tokens-menubar/agent-usage.json` (0700 directory, 0600 file). Corrupt existing files are preserved rather than silently overwritten. Export is local and explicitly chosen; it may include account labels, so share it deliberately. Keys are never exported.
- OpenRouter: opt-in implementation of the official `GET https://openrouter.ai/api/v1/key` endpoint for one key's spend, cap, remaining and reset rule. The screen labels it per-key, not account balance or subscription. Credentials are collected in an AppKit secure field and stored in macOS Keychain. No model calls, no cookie scraping, no key upload to tokens.ci, no redirect forwarding; five-minute refresh backoff. An API key is not intrinsically read-only: the connection prompt explicitly recommends a dedicated low-limit key. This adapter has fixture/parser tests, not a live-account/Keychain test.
- Catalog: 67 entries including one custom-service entry, not 66 integrations. Includes personal agents, coding clients and API accounts. Each entry has its official/upstream source, unit and integration caveat. Unknown quotas are not zero. The upstream coding-client list is evidence of possible local/session support, not proof that the current user's CLI is installed/configured or that their service quota is connected.

No usage records or credentials are seeded. No service is connected just because it appears in the directory. Values become stale after one day, at their period end or their stated reset; old values are retained and marked, not replaced with fake zeroes.

## Automatic paths: what actually happens

These connections are disabled until explicitly enabled. They do not log into services on the user's behalf, read credential files or generate model calls. They are separate scopes and are never summed into tokens.ci totals. The available interface is not proof that a particular account returned data.

- **Codex:** uses the official locally installed and logged-in CLI (`codex app-server`) with `initialize`, `account/rateLimits/read` and `account/usage/read`. Displays the returned primary/secondary used and remaining percentages, resets and account lifetime token activity where that endpoint is supported. It is the account's Codex scope, not all ChatGPT conversations, API billing or a model-token-to-credit conversion. Enable in My usage. Reads are bounded and throttled to once per five minutes while the window is open; failed reads retain dated values. Official source: [Codex app-server](https://developers.openai.com/codex/app-server). The real unauthenticated CLI returned an authentication failure in the development probe; no signed-in account values were tested.
- **Claude Code:** one-time confirmation installs TokensBar's supported local `statusLine` command in `~/.claude/settings.json`. When a new Claude Code session emits status JSON, the helper keeps only `rate_limits` percentages/reset times and the last session's estimated cost in a 0600 local file. Pro/Max rate windows appear only if that CLI supplies them. No cookie, API key, conversation, workspace path or session ID is stored by the bridge. Existing custom status lines are not overwritten; disabling removes only this exact bridge and its sanitized data. Put TokensBar in a stable Applications path first. Source: [Claude Code statusline](https://code.claude.com/docs/en/statusline). API cost is not personal-plan quota; no first-hand authenticated rate-limit report has been tested.
- **Muse Code:** optional `muse serve` → MSP `usage/read` returns the host's last observed subscription percentage windows. This is **not Meta Muse the personal agent**. A newly started host may have no cached observation. TokensBar does not call experimental `usage/refresh`, mint a key or start a model turn. Source: [official documented MSP wire protocol](https://meta-models.github.io/muse-code-sdk/1.4/guides/msp-wire/). Fixture-tested only; user CLI/version/account availability is unverified.
- **tokens.ci / OpenRouter:** the actual submitted client-day data and optional official per-key adapter described above remain available. A catalog entry does not create a connection.

The four requested personal agents—Meta Muse, Grok Bot, Manus Cue and Wabi—still have no verified supported automatic personal-allowance adapter in this candidate. Consumer settings pages, developer/API balances, team admin endpoints and coding-session logs are not interchangeable. No cookie scraper or forbidden website automation was added. The broad directory is a reference, not the promised automation; repeatedly typing numbers is not required to use the automatic paths.

## Four compact improvements

Open Actions → Usage & display (or the context menu) for a compact four-tab native window; the existing panel modules keep their order.

1. **Trends:** today compared with the previous seven complete UTC-day records from the same tokens.ci submitted data. Every required day must be present; missing is not zero. Today is in progress and only current to the last submission. The largest model token delta is shown only when every day's model detail sums to that day's total; otherwise no model attribution is invented. A zero baseline has no percentage comparison. Local scans are not compared against all-device history.
2. **Data health:** last fetch attempt, successful fetch, server submission, CLI attempt and successful today scan are separate. Network/auth/status errors retain old values with dates. CLI missing, unlaunchable, unsuccessful and unparseable states have different explanations. Retry reads only; Submit uses the existing explicit local-submission action. Read-token settings and the official CLI installation guide remain actual working actions. No reinstall or upload happens on refresh.
3. **Alerts:** daily estimated-USD threshold controls the existing amber/red menu colour. A separate estimated month-end threshold uses the existing local calendar-month pace. Each threshold can notify at most once per UTC day, six hours or hour, or not notify. All fields persist on this Mac. Only successful observations no older than 15 minutes qualify; failure/unknown/stale data cannot trigger. macOS permission is requested only after explicitly saving enabled notifications. Accepted by macOS is not proof a banner was displayed; Focus/system settings can suppress it. No production notification was sent in CI.
4. **Menu bar:** checkboxes and up/down controls choose and order today tokens, estimated cost and rank. At least one stays visible. Changes apply immediately and persist in UserDefaults, overriding corresponding config defaults; no config-file editing is needed. Rank scope remains the existing Today/All-time choice.

## Build and verification

On macOS 13+ with Xcode Command Line Tools, the existing build command `./build.sh` includes all new Swift sources; `./build.sh --universal` creates both architectures. Run `./Tests/run.sh` for the deterministic checks.

Core checks include 76 existing pure-Swift regressions, 57 Agent storage/catalog/parser checks and 35 automation/trend/alert/preferences checks. Native checks cover local JSON-RPC framing/timeout, reversible Claude config preservation, display reorder/toggle/last-item guard and persistence, plus the existing accent and Agent search/filter paths. Tests use disposable files and synthetic fixtures, not real accounts or a notification send.

Native screenshots are actual AppKit light/dark English/Chinese offscreen renders at 2×. Demo values and failure states are labelled. They are not proof of account connection or a complete manual end-to-end acceptance test.

Unverified: authenticated Codex/Claude/Muse Code account results, real Keychain/OpenRouter behavior, user-device CLI configuration, macOS notification banner delivery and complete manual popup/resize acceptance. No personal-agent web scraping exists. The universal candidate is ad-hoc signed, not Apple-notarized, and Gatekeeper can block first open. The independent candidate branch is `wabi/agent-usage-candidate-20261028`; no main merge, tag or release is made by this work. See the delivery note for the exact successful native CI run and binary hash.
